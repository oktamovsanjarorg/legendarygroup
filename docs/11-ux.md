# 11 — UI/UX printsiplari va ekranlar xaritasi

> Maqsad: Telegram ichida **native ilova** hissi, web panelda **tez ish joyi**.
> Har bir UI vazifasi shu hujjatga mos bo'lishi shart; dizayn natijalari `docs/ux/`da (T-017a–c).

## 1. Kanallar o'rtasidagi chegara (eng muhim qaror)

| Kanal         | Vazifasi                                                                                                                                                                                                                                                    | Nima QILINMAYDI                                                                                                                |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Bot**       | 1) bildirishnomalar; 2) har xabarda **Mini App'ning aynan kerakli ekraniga** olib boradigan tugma (`startapp` deep link); 3) chatga tabiiy oqimlar: telefon raqamni ulashish, chek rasmini yuborish, Excel fayl yuborish, tasdiqlash so'roviga inline javob | Ko'p qadamli menyular, ro'yxatlar, formalar — bularning hammasi Mini App'da                                                    |
| **Mini App**  | Barcha interaktiv ish: Ustoz (to'liq), Ota-ona (to'liq), Director/Admin (mobil ish: navbat, so'rovlar, dashboard)                                                                                                                                           | Katta jadvallar, murakkab hisobotlar, sozlamalar — web'da                                                                      |
| **Web panel** | Director va Admin'ning stol ish joyi: ro'yxatlar, jadvallar, to'lov kiritish, hisobotlar, sozlamalar                                                                                                                                                        | Telefon uchun moslashtirilmaydi (≥ 1280 px asosiy, planshet ≥ 1024 px qo'llab-quvvatlanadi); telefonda — Mini App xodim rejimi |

**Qoida:** bitta oqim bitta joyda to'liq bo'ladi. Chek yuborish: botga rasm tashlansa ham, Mini App'dan yuborilsa ham **bitta backend oqimi**, va bot rasmni olgach Mini App'ning tasdiqlash ekranini ochadi (summa, farzand, izoh) — ikki xil forma yo'q.

**Xabarlarni yangilash:** holati o'zgaradigan xabarlar (chek "Tekshirilmoqda" → "Tasdiqlandi") yangi xabar bilan emas, **eski xabarni tahrirlash** bilan yangilanadi — chat tartibli qoladi. Muhim natija (tasdiqlandi + PDF) — alohida xabar.

## 2. Ekranlar xaritasi

### Mini App — Ustoz (pastki menyu: 4 tab)

```
[Bugun]            bugungi darslar (vaqt, guruh, xona) → Davomat ekrani
                   belgilanmagan davomatlar ogohlantirishi
[Guruhlarim]       guruh → o'quvchilar ro'yxati → o'quvchi profili (davomat, baholar, izohlar)
                        → testlar → test natijalari / import ko'rib chiqish
                        → e'lon yuborish (faqat main)
[Jadval]           haftalik kalendar, o'rinbosar darslari belgilangan
[Profil]           oylik hisob (oylar bo'yicha, tafsilot), sozlamalar, rol almashtirish
```

**Davomat ekrani** (eng ko'p ishlatiladigan): o'quvchilar ro'yxati, hamma standart ✅; qatorni bosish → ❌; uzoq bosish → menyu (⏰ kech qoldi + daqiqa, 📝 sababli); oldindan "sababli" xabar berilganlar belgili; har qatorda baho qo'yish (guruh sozlamasiga ko'ra); MainButton "Saqlash (18/20 keldi)". Saqlashdan keyin 3 daqiqa "O'zgartirish" mumkinligi ko'rsatiladi (BR-31).

### Mini App — Ota-ona (pastki menyu: 4 tab)

```
[Asosiy]     farzand kartochkasi (bir nechta bo'lsa yuqorida almashtirgich)
             bugun: keldi/kelmadi, keyingi dars, balans holati (qarz bo'lsa — "To'lash" tugmasi)
[Natijalar]  davomat kalendari, baholar, ustoz izohlari, test natijalari, progress grafigi
[To'lovlar]  balans, invoice'lar, to'lovlar tarixi + PDF cheklar, "To'lov qilish" → rekvizit → chek yuklash
[Ko'proq]    "Kela olmaydi" xabari, murojaat, bildirishnoma sozlamalari, jadval
```

### Mini App — Director / Admin (xodim rejimi)

```
[Bugun]      tushum, davomat %, belgilanmagan darslar, kelmaganlar
[Navbat]     chek tasdiqlash navbati (rasm to'liq ekran, zoom, Tasdiqlash/Rad etish) — badge bilan
[So'rovlar]  tasdiqlash so'rovlari (faqat Director)
[Qidiruv]    o'quvchi topish → kartochka (qarz, ota-ona telefoni — qo'ng'iroq tugmasi)
```

### Web panel — Director / Admin (chap menyu)

```
Bosh sahifa (dashboard)
O'quvchilar · Lidlar · Guruhlar · Jadval (kalendar) · Davomat
To'lovlar (kiritish, navbat, qarzdorlar, kassa) · Chegirmalar
Natijalar (testlar, importlar)
Xabarlar (e'lonlar, murojaatlar, yetib bormaganlar)
Moliya (xarajatlar, P&L) · Oyliklar          ← ruxsatga qarab
Hisobotlar · Prognozlar
Xodimlar · Sozlamalar · Audit               ← faqat Director
```

`Ctrl+K` — buyruqlar paneli (o'quvchi qidirish, "to'lov kiritish", "guruh ochish"). To'lov kiritish istalgan sahifadan `Alt+P`.

## 3. Dizayn tizimi

## 4. Interaksiya qoidalari

1. **Telegram native boshqaruvlari:** orqaga — faqat `BackButton`; ekranning asosiy amali — `MainButton` (pastda, bitta); ikkinchi amal — `SecondaryButton`; ichki "Orqaga" tugmalari chizilmaydi.
2. **Haptic:** muvaffaqiyat → `notificationOccurred('success')`, xato → `error`, holat almashtirish → `selectionChanged`. Haddan tashqari ko'p emas.
3. **Saqlanmagan o'zgarish** bo'lsa (davomat, forma) — `enableClosingConfirmation`.
4. **Tezlik hissi:** optimistik yangilash (davomat, baho); ma'lumot kutilayotganda skeleton (spinner emas); ekranlar oldindan yuklanadi (prefetch) — "Bugun" ochilganda birinchi guruh ro'yxati tayyor turadi.
5. **Tasdiqlash o'rniga bekor qilish (undo):** qaytariladigan amallar (davomat o'zgartirish, xabarni arxivlash) — "Bekor qilish" snackbar, 5 s. Qaytarib bo'lmaydigan amallar (storno, rad etish, e'lon yuborish) — tasdiqlash oynasi, amal nomi tugmada ("Rad etish", "OK" emas).
6. **Har ekranning 5 holati majburiy:** yuklanmoqda · bo'sh (nima qilish kerakligi bilan) · xato (qayta urinish) · offline · ruxsat yo'q. Ular dizaynda chiziladi va Storybook'da ko'rinadi.
7. **Offline:** tarmoq yo'qligi yuqorida ingichka chiziq bilan ko'rsatiladi; davomat va baho lokal navbatda saqlanadi, "Sinxronlanmadi (2)" belgisi; qayta ulanganda avtomatik yuboriladi.
8. **Formalar:** validatsiya maydon yonida, yozish paytida emas — maydondan chiqqanda; telefon `+998` maskasi; summa — avtomatik bo'shliq bilan formatlash, raqamli klaviatura.
9. **Deep link'lar:** har bildirishnoma tugmasi aniq ekranni ochadi (`startapp=att_<lessonId>`, `startapp=pay_<studentId>`); deep link ruxsatsiz obyektga olib borsa — tushunarli "ruxsat yo'q" ekrani.
10. **Desktop Telegram:** Mini App 384–600 px kenglikda ham buzilmaydi.

## 5. O'lchanadigan UX mezonlari (qabul qilish uchun)

| Ssenariy                                  | Mezon                                 |
| ----------------------------------------- | ------------------------------------- |
| Ustoz 20 kishilik davomat (2 ta kelmagan) | ≤ 4 teginish, ≤ 20 s                  |
| Ota-ona chek yuborishi (bot xabaridan)    | ≤ 5 qadam, ≤ 60 s                     |
| Admin naqd to'lov kiritishi               | ≤ 30 s, sichqonchasiz bajarish mumkin |
| Admin chek tasdiqlashi                    | ≤ 3 teginish                          |
| Mini App sovuq ochilish (4G)              | ≤ 2 s gacha birinchi foydali ekran    |
| Ekranlar o'tishi                          | ≤ 100 ms javob (optimistik/kesh)      |
| Lighthouse (Mini App build)               | Performance ≥ 90, Accessibility ≥ 95  |

Bu mezonlar Playwright E2E testlarida (qadamlar soni) va real qurilmada qo'lda tekshiriladi.

## 6. Bot xabarlari uslubi

- Tuzilma: **sarlavha (emoji + qalin)** → 1–3 qator mazmun → tugma(lar). Masalan:
  ```
  ❌ Ali Valiyev darsga kelmadi
  Ingliz tili · B1-guruh · bugun 15:00
  [Batafsil]  [Sababini yozish]
  ```
- Emoji faqat holat belgisi sifatida (✅ ❌ ⏰ 💳 📄 📊), bezak uchun emas.
- Har xabar shablonda (`packages/i18n`), dizayn katalogida namunasi bilan.
- Bitta hodisa — bitta xabar; tez-tez sodir bo'ladigan narsalar (baholar) — sozlamaga ko'ra kunlik yig'ma xabar.

## 7. Komponentlar ishlab chiqish tartibi

1. Tokenlar va komponentlar `ui-tg`/`ui-web`da, har biri **Storybook**'da barcha holatlari bilan (light/dark, bo'sh, xato, uzun matn).
2. Ekran avval Storybook'da test ma'lumoti bilan yig'iladi, keyin API'ga ulanadi.
3. Vizual regressiya — Playwright screenshot testlari asosiy ekranlar uchun.
